Core idea

不是讓 AI 自由幻想，而是讓生成結果可以被檢查。

RoomQuest 把創意與驗證分開：AI 負責生成內容，Python 負責檢查明確規則，主持人保留最後決定權。

01

AI generation

AI 出題

依據場景 JSON 選擇物品、規劃順序，再撰寫故事、線索與分層提示。

02

Rule verification

Python 驗題

檢查物品是否存在、條件是否唯一、答案是否固定，以及操作是否安全。

03

Human in the loop

主持人核准

修正場景資料、查看驗證報告，最後選擇修改、重新生成或發布遊戲。

Workflow

兩種角色，一條可追蹤的資料路徑。

所有 AI 生成與驗證都在主持人端完成；玩家端只載入核准後的遊戲資料，不會在遊玩途中臨時呼叫 AI。

  1. 1
    提供並確認場景

    上傳照片，修正物品、屬性、可碰觸性與是否會變動。

  2. 2
    計算可用物品

    Python 找出在已確認場景中可以被唯一指認的候選物品。

  3. 3
    規劃與撰寫關卡

    AI 先建立關卡鏈，再產生正式線索與分層提示。

  4. 4
    驗證並退回修改

    未通過時回傳具體原因，最多自動修改兩次。

  5. 5
    預覽與核准

    主持人確認後，匯出唯一交接檔案 game.json。

  1. 1
    載入核准遊戲

    玩家端只讀取主持人發布的 game.json。

  2. 2
    觀察現場並作答

    依照目前線索尋找物品，輸入數字、選項或短詞。

  3. 3
    正規化與比對

    Python 比對答案；答錯可查看由模糊到明確的提示。

  4. 4
    解鎖下一關

    完成所有關卡後，組合取得的數字成為最終密碼。

  5. 5
    顯示通關結果

    呈現完成時間、提示使用次數及遊戲結局。

Architecture

核心價值在 Harness，而不只是模型。

RoomQuest 將課堂中的 Planning、Tool Use 與 Reflection 串成可檢查的工作流程，並保留人工確認的停損點。

照片或主持人手動輸入

02AI planning

03Python tools

唯一性、安全性、答案來源與流程驗證

04Reflection loop

具體錯誤回饋與局部重寫

05Approved output

主持人核准的 game.json
