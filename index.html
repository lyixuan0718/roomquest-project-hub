生成式 AI 應用｜第九週作業延伸

一張教室照片，能不能變成真的玩得完的解謎遊戲？

這是我為期末專案提出的 RoomQuest。它不只是請 AI 寫幾道謎語，而是先把真實空間整理成資料，再讓 AI 出題、讓程式檢查、最後由人決定能不能發布。

我想做的不是「ChatGPT 密室逃脫」，而是一個能說明生成內容如何被限制、檢查與修正的作品。

01

發想從哪裡來

把 AI 從「聊天視窗」帶回真實空間。

一般密室逃脫需要先布置場地、準備道具與撰寫固定題目。我想測試：如果教室裡本來就有公告欄、椅子、水壺與門牌，生成式 AI 能不能利用這些東西，快速排出一場只屬於這個空間的遊戲？

最大的難點不是「能不能生成文字」，而是題目有沒有引用不存在的物品、是否同時指向兩個答案、答案會不會隨時間改變，以及操作是否安全。這些問題不能只靠另一個 AI 說「看起來沒問題」。

創意內容交給生成式 AI；能以規則確認的部分交給 Python；最後決定權留給主持人。
02

系統流程

主持人先把遊戲做完，玩家才開始玩。

遊玩時不會臨時呼叫 AI。所有線索都要先通過程式檢查與主持人核准，再存進 game.json。

  1. 01
    整理場景

    照片由多模態模型解析；主持人修正名稱、數量、文字、位置與可碰觸性。

    人＋AI
  2. 02
    挑出可用物品

    Python 找出在已確認資料中可以被唯一指認、而且答案固定的物品。

    Python
  3. 03
    規劃關卡

    AI 先安排物品、答案來源與順序，再撰寫線索及分層提示。

    AI
  4. 04
    驗證與退回

    檢查存在性、唯一性、順序、安全與答案來源；不合格就回報具體原因。

    Python
  5. 05
    預覽並發布

    主持人手動確認完整遊戲，再匯出核准版 game.json。

    人
  1. 01
    載入遊戲

    玩家端只讀取主持人核准的 game.json。

    資料
  2. 02
    閱讀線索

    玩家不知道候選物品清單，必須觀察完整空間。

    人
  3. 03
    輸入答案

    Python 正規化數字、選項或短詞後進行比對。

    Python
  4. 04
    解鎖下一關

    答錯可以查看分層提示；答對才會取得下一條線索。

    介面
  5. 05
    組合最終密碼

    完成所有關卡後，組合每關得到的數字並顯示結果。

    介面

06

本週作業重點

AGENTS.md 讓下一次修改有規則可循。

它不只寫「請維持相同風格」，而是記錄專案目的、檔案責任、場景資料格式、命名方式、誠實呈現原則與完成前必須通過的檢查。

  • 新增案例：只改 data/scenarios.json，不用複製整段首頁 HTML。
  • 新增頁面：沿用相同版面、導覽與檔名規則，並更新 README。
  • 修改完成：必須通過資料驗證、JavaScript 語法檢查及桌機／手機預覽。
